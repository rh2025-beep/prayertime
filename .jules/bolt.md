## 2024-03-01 - Avoid Synchronous Disk I/O & Heavy Instantiations in High-Frequency Interval Loops
**Learning:** This codebase uses a 1-second `setInterval` in `App.jsx` to update a `currentTime` state, triggering global re-renders. Within the render and effect cycles driven by this tick, calling `new Intl.DateTimeFormat()` and `localStorage.setItem` synchronously caused significant main thread blocking, even though the data rarely changes second-by-second. The `DateTimeFormat` object is notoriously expensive to initialize across JS engines.
**Action:** When working with high-frequency interval-driven states (like timers or clocks), always `useMemo` expensive object initializations like `Intl.DateTimeFormat`. For sync effects tied to these fast-updating states, implement dirty-checking using `useRef` to stringify and compare payloads before executing blocking native bridge calls or Disk I/O (like `localStorage`). Additionally, when using `Intl.DateTimeFormat` with `{ hourCycle: 'h23' }` prevents midnight from being formatted as `24:xx`, avoiding `new Date()` parsing errors.
