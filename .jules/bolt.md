## 2024-05-19 - Widget sync dirty-checking optimization
**Learning:** In `App.jsx`, a 1-second interval continuously updates state (`timeLeft`, `progressPercent`). An effect depends on these and recalculates a complex `widgetPayload` object, then attempts to synchronously write it to `localStorage`, `Capacitor.Preferences`, and a Native `PrayerWidget` plugin every single second. However, the payload values (especially the countdown string in minutes) typically only change once a minute. This results in ~59 redundant, expensive, synchronous I/O and blocking native IPC calls every minute per client.
**Action:** Implemented a dirty-checking mechanism. By stringifying the `widgetPayload` and caching it in a `useRef`, we can compare the current payload against the previous one. If there's no change, we skip the expensive disk writes and native plugin calls, drastically reducing overhead and blocking operations in the tight 1-second interval loop.
