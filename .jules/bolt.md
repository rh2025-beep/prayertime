## 2024-05-15 - Memoizing Intl.DateTimeFormat and Dirty-Checking Synchronous Calls
**Learning:** High-frequency `setInterval` loops (like the 1-second clock timer) cause `toLocaleString` with a `timeZone` option to consume excessive main thread time (~2+ seconds per 10k calls vs ~100ms for a memoized `Intl.DateTimeFormat`). Additionally, updating widget state via synchronous `localStorage.setItem` and Capacitor native plugins every second causes massive main-thread blocking, even if the actual visible string only changes every minute.
**Action:** Always memoize `Intl.DateTimeFormat` inside `useMemo` when parsing timezones in high-frequency React effects. Use a `useRef` to stringify and dirty-check payload objects before writing to `localStorage` or native bridges in high-frequency loops.
