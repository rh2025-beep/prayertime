## 2024-05-24 - Intl.DateTimeFormat caching is 10x faster than toLocaleString
**Learning:** In high-frequency React `useEffect` loops (e.g. running 60fps or every second like our clock), `toLocaleString` is a significant performance bottleneck when calculating timezones since it implicitly instantiates a new `Intl.DateTimeFormat` internally on every call.
**Action:** When formatting dates for timezones in high-frequency loops or renders, create a cached `Intl.DateTimeFormat` instance using `useMemo` outside the render loop and use `formatToParts()` to parse the localized time, ensuring robust memory/CPU conservation. Note that `hour12: false` with `formatToParts` outputs `24` at midnight, which `new Date()` fails to parse; `hourCycle: 'h23'` must be used to keep hours in `00-23` range.
