## 2026-09-12 - Expensive implicit Intl instantiations in high-frequency React interval loops
**Learning:** Utilizing `Date.toLocaleString()` inside a 1-second `setInterval` loop implicitly instantiates a new `Intl.DateTimeFormat` object on every execution. In this application, calling `toLocaleString("en-US", { timeZone: metaInfo.timezone })` multiple times inside the render loop (and effect dependencies) resulted in hundreds of milliseconds of main-thread blocking time per thousand executions, creating a severe performance bottleneck.
**Action:** Always extract and memoize `Intl.DateTimeFormat` with `useMemo` based on the timezone string when dealing with variable timezones. Use `hourCycle: 'h23'` to avoid parsing bugs with `new Date(formattedStr)`. Additionally, for high-frequency interval effects (e.g., syncing home screen widgets every second), wrap synchronous disk I/O (`localStorage.setItem`) and native plugin calls in a dirty-check using `useRef` to avoid redundant blocking operations when the payload hasn't changed.
