## 2024-05-19 - Avoid Date.prototype.toLocaleString in Render Loop
**Learning:** In React apps, repeatedly invoking `Date.prototype.toLocaleString()` with timezone configurations inside the main render loop or a high-frequency hook (`useEffect` with timer) creates massive overhead. In local benchmarks, `toLocaleString` parsing takes ~385ms for 1k iterations vs ~6ms for caching `Intl.DateTimeFormat`.
**Action:** Use a memoized `useMemo(() => new Intl.DateTimeFormat(...), [dependencies])` instance whenever possible to parse or format dates instead of inline `toLocaleString()` calls, especially in timer-heavy contexts. Remember to use `hourCycle: 'h23'` rather than `hour12: false` when using it to initialize new `Date` objects to avoid `24:xx:xx` "Invalid Date" parsing errors.
