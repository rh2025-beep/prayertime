## 2026-09-09 - Add ARIA Roles to Modals
**Learning:** Found an accessibility issue pattern specific to this app's components where custom modal views (`.fullscreen-view`, `.modal-content`) were built using standard `<div>` elements but were completely missing standard ARIA modal attributes (`role="dialog"`, `aria-modal="true"`, and `aria-label`). This pattern existed across Settings, Location Search, and Qibla modals, severely degrading the experience for screen reader users by not announcing the new interactive context when modals overlay the screen.
**Action:** Always ensure that custom modals in this repository, including both fullscreen and floating overlay components, explicitly include `role="dialog"`, `aria-modal="true"`, and a descriptive `aria-label` (often sourced from the localized `str` object) on the outermost container element.
